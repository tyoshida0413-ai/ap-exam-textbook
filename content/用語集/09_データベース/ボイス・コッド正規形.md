# ボイス・コッド正規形

> **すべての決定項が候補キーになっている状態**。
> [[第3正規形]]をさらに厳しくしたもの。

## なぜそうなるのか

### 第3正規形でも問題が残ることがある

[[第3正規形]]の条件は「**非キー属性が**推移的関数従属していないこと」です。
この条件は非キー属性についてしか言っていません。
そのため、**候補キーが複数あって列が重なっている**表では、まだ更新時異状が残ります。

```
受講表（学生番号, 科目, 担当教員）
   前提：1科目に複数の教員、1教員は1科目だけ担当

   候補キー：｛学生番号, 科目｝ と ｛学生番号, 担当教員｝  ← 重なっている
   担当教員 → 科目     ← この決定項「担当教員」は候補キーではない
```

担当教員が決まれば担当科目が決まります。
しかし「科目」は候補キーの一部なので**非キー属性ではなく**、第3正規形の条件には引っかかりません。
それでも、その教員の受講者がいなくなると、**その教員が何を担当していたかが消えてしまいます**（削除異状）。

### BCNFの条件

そこで、条件を非キー属性に限定せず、こう言い換えます。

> **関数従属の左側（決定項）は、必ず候補キーでなければならない。**

上の例では `担当教員 → 科目` の決定項が候補キーでないためBCNFではありません。
`教員表（担当教員, 科目）` と `受講表（学生番号, 担当教員）` に分解すると満たします。

### どこまで覚えるか

応用情報では、**定義（すべての決定項が候補キー）と、第3正規形より厳しいという位置づけ**を
押さえれば十分です。第4正規形・第5正規形も、名前と順序だけで足ります。

## 混同しやすい語

| 語 | 決定的な違い |
|---|---|
| [[第3正規形]] | 条件が**非キー属性についてだけ**。BCNFは**すべての決定項**に条件を課す |
| [[候補キー]] | BCNFの**判定基準**そのもの。「決定項が候補キーか」を見る |
| [[推移的関数従属]] | 第3正規形が排除する対象。BCNFはそれを消した後にも残る問題を扱う |

## 試験での問われ方

- 「すべての決定項が候補キーである状態は」→ **ボイス・コッド正規形**
- 正規形の厳しさの順序を問う出題 → 第1 → 第2 → 第3 → **BCNF** → 第4 → 第5
- ひっかけ：「第3正規形ならBCNFである」＝**誤り**。逆（BCNFなら第3正規形）は正しい
