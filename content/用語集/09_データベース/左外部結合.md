# 左外部結合

> **左側の表の行をすべて残し、右側に対応がなければNULLで埋める結合**。
> 対応がある行だけを残す[[内部結合]]と対になる。

## 日常のたとえ

部署の一覧と社員の一覧を突き合わせて名簿を作るとします。
**まだ誰も配属されていない部署**を、名簿から消してよいでしょうか。
「部署の一覧」として使うなら消してはいけません。
左外部結合は「**左の表は1行も落とさない**」という約束です。

## なぜそうなるのか

```
部署表                     社員表
部署コード 部署名          社員番号 氏名  部署コード
  D01     営業               1001  田中   D01
  D02     経理               1002  佐藤   D01
  D03     法務                                ← D03に社員はいない

【内部結合】D03が消える
  D01 営業 1001 田中
  D01 営業 1002 佐藤

【左外部結合】部署表を左に置く → D03が残る
  D01 営業 1001 田中
  D01 営業 1002 佐藤
  D03 法務 NULL NULL          ← 対応がないのでNULLで埋まる
```

### 種類は3つ

| 種類 | どちらを必ず残すか |
|---|---|
| **左外部結合**（LEFT OUTER JOIN） | 左の表 |
| 右外部結合（RIGHT OUTER JOIN） | 右の表 |
| 完全外部結合（FULL OUTER JOIN） | 両方 |

左右はFROM句に書いた順で決まります。表の順番を入れ替えれば、左外部結合と右外部結合は同じ結果になります。

### 落とし穴1：COUNT(\*) で数えると1になる

「社員がいない部署も含めて、部署ごとの社員数を出す」という定番問題があります。
左外部結合まで正しく書けても、`COUNT(*)` と書くと**社員0人の部署が「1」と数えられます**。
NULLで埋まった行も**1行として存在している**からです。

正しくは `COUNT(社員番号)` と書きます。[[集約関数]]はNULLを無視するため、0になります。

### 落とし穴2：WHERE句で台無しにする

右側の表の列にWHERE条件を書くと、**NULLの行が条件に合わずに消えてしまい、内部結合と同じ結果**になります。
外部結合を保ったまま絞りたいときは、**ON句のほうに条件を書きます**。

## 混同しやすい語

| 語 | 決定的な違い |
|---|---|
| [[内部結合]] | **両方に対応がある行だけ**を残す。左外部結合は**左を必ず残す** |
| [[直積]] | 条件なしの総当たり。外部結合は**共通の列で対応づける** |
| [[NULL]] | 外部結合が**作り出す**もの。集約や条件式での扱いに注意が要る |

## 試験での問われ方

- 「〜がない場合も含めて」「〜も一覧に出す」という語が出たら**外部結合**を疑う
- 結合結果の**行数を答えさせる**出題。NULLで埋まる行を数え忘れないこと
- ひっかけ：`COUNT(*)` を使わせて、社員0人の部署を1と数えさせる
