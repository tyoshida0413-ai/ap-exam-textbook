# NULL

> **値が不明・未定・非該当であることを表す「状態」**。0や空文字とは別物。
> 比較演算子では判定できず、`IS NULL` を使う。

## 日常のたとえ

アンケートの回答欄が空白だったとき、「0と答えた」のとは違います。
「まだ答えていない」だけで、本当の値は分かりません。
NULLはこの空白そのもので、「値が入っていない」という状態を指します。

## なぜそうなるのか

### 比較すると「不明」になる（3値論理）

普通の論理は真か偽の2つですが、SQLは**真・偽・不明**の3つで判定します（3値論理）。

`給与 = NULL` は「不明な値と等しいか」という問いになり、答えは真でも偽でもなく**不明**です。
WHERE句は**真の行だけ**を返すので、1件も取れません。

| 書き方 | 結果 |
|---|---|
| `WHERE 列 = NULL` | 常に不明 → **1件も返らない** |
| `WHERE 列 <> NULL` | 常に不明 → **1件も返らない** |
| `WHERE 列 IS NULL` | **これが正解** |
| `WHERE 列 IS NOT NULL` | NULLでない行を返す |

> **NOT INの罠**：`WHERE 部署 NOT IN (SELECT 部署 FROM 表B)` の副問合せ結果にNULLが混ざると、
> 比較がすべて不明になり、**結果が1件も返らなくなります**。
> `NOT EXISTS` に書き換えるのが定石です（→ [[EXISTS述語]]）。

### 集約関数はNULLを無視する

`COUNT(*)` は行数をそのまま数えますが、`COUNT(列)` は**その列がNULLでない行だけ**を数えます。
`AVG(列)` もNULLを除いた行数で割るため、**NULLを0とみなして計算するわけではありません**。

```
給与： 300, NULL, 500

  COUNT(*)    = 3
  COUNT(給与) = 2
  AVG(給与)   = (300+500) ÷ 2 = 400
                0として扱うなら (300+0+500) ÷ 3 = 266.6… だが、そうはならない
```

また、`NULL + 100` のような演算や文字列連結の結果も**NULLになります**。

### 制約との関係

| 制約 | NULLの扱い |
|---|---|
| [[主キー]] | **NULL不可**。不明なもので行を識別できないため（実体整合性） |
| [[一意性制約]] | **NULLは複数あってよい**。NULLどうしは等しいと判定されないため |
| [[外部キー]] | **NULLを許す**。相手が未定であることを表せる |
| NOT NULL制約 | NULLの格納そのものを禁止する |

## 混同しやすい語

| 語 | 決定的な違い |
|---|---|
| 0・空文字 | **値が入っている**。NULLは値が入っていない状態 |
| [[左外部結合]] | 対応がない箇所を**NULLで埋める**結合。NULLが生まれる代表的な場面 |

## 試験での問われ方

- 「NULLの説明として適切なものは」→ **値が不明・未定であることを示す状態**
- 「NULLを検索する条件式は」→ **IS NULL**。`= NULL` ではない
- 「AVGはNULLを0として計算する」＝**誤り**
- SQLの結果行数を答えさせる問題で、NULLを含む行が消えるかを問う出題
