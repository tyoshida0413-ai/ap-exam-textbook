# データベース 混同しやすい語の一覧

> **2つの使い方がある**
> (1) **学習用**：試験で狙われるのは「似た語の取り違え」。ここだけ潰せば失点が大きく減る
> (2) **作業用**：用語集を書くときの設計図（→ 3章の難語リストが執筆の優先順位になる）

> **この分野の大原則**
> データベースの用語は、**ほとんどが「トレードオフ」の片側**です。
> 正規化⇔非正規化、索引あり⇔なし、ロック細⇔粗、分離レベル強⇔弱。
> **「何を得て、何を失うのか」をセットで言えるか**が、そのまま得点力になります。

## 1. 最重要の混同ペア（ここを間違えると失点が大きい）

| 対比 | 決定的な違い | ひっかけの出方 |
|---|---|---|
| [[射影]] ↔ 選択 | **列を絞る**（縦に切る）／**行を絞る**（横に切る） | 説明を入れ替える。**最頻出** |
| [[第2正規形]] ↔ [[第3正規形]] | **主キーの一部**で決まるものを排除／**主キー以外**で決まるものを排除 | 部分関数従属と推移的関数従属を入れ替える |
| [[部分関数従属]] ↔ [[推移的関数従属]] | キーの一部 → 非キー／非キー → 非キー | どちらが第2でどちらが第3か |
| [[GROUP BY句]] の [[HAVING句]] ↔ WHERE | **グループ化の後**に効く／**前**に効く。集約関数を書けるのはHAVINGだけ | 適用順序を逆にする |
| [[内部結合]] ↔ [[左外部結合]] | 両方に対応がある行だけ／**片方は全部残しNULLで埋める** | 「〜がない場合も含めて」の要件で内部結合を選ばせる |
| [[ロールバック]] ↔ [[ロールフォワード]] | **更新前ログ**で巻き戻す／**更新後ログ**で進める | 使うログと、コミット済みかどうかを入れ替える |
| [[専有ロック]] ↔ 共有ロック | 読み書きとも禁止／**読み取りは許す** | どちらが読み取りを許すか |
| [[ダーティリード]] ↔ [[反復不能読み取り]] ↔ [[ファントムリード]] | **未確定を読む**／**値が変わる**／**行数が変わる** | 3つを入れ替える |
| [[正規化]] ↔ [[非正規化]] | 重複をなくす（矛盾を防ぐ）／**あえて重複させる**（結合を減らして速くする） | 「正規化すると必ず速くなる」＝誤り |
| [[OLTP]] ↔ [[OLAP]] | **日々の業務処理・更新中心・正規化**／**分析・参照中心・非正規化** | 設計方針が正反対である点 |
| [[概念スキーマ]] ↔ [[外部スキーマ]] ↔ [[内部スキーマ]] | 全体の論理構造／**利用者から見た形**／**物理的な格納方法** | 外部と内部を入れ替える |
| 論理データ独立性 ↔ 物理データ独立性 | **概念を変えても外部に影響しない**／**内部を変えても概念に影響しない** | どちらの層の話か |
| [[主キー]] ↔ [[候補キー]] | 候補キーから**1つ選んだもの**／一意に識別できる**すべての**組 | 候補キーは複数あってよい点 |
| [[外部キー]] ↔ [[主キー]] | **他表の主キーを参照する**／自表の行を識別する | 参照整合性が働く方向 |
| [[2相コミット]] ↔ [[2相ロッキング]] | **分散DBの確定手順**／**ロックの取得と解放の規則** | 名前が似ているだけで別物 |
| [[レプリケーション]] ↔ [[シャーディング]] | **同じデータを複製**する（可用性）／**データを分割**して配る（負荷分散） | 複製と分割を入れ替える |
| [[データウェアハウス]] ↔ [[データマート]] ↔ [[データレイク]] | 全社の分析用倉庫／**部門向けに切り出したもの**／**加工前の生データ置き場** | 3つの関係を入れ替える |
| [[インデックス]] | 検索は速く、**更新は遅く**なる | 「付ければ必ず速くなる」＝誤り |

## 2. セットで理解すべき語のかたまり

### (A) 正規化は「矢印を追い出す」作業

[[関数従属]] → [[第1正規形]]（繰り返しをなくす）→ [[第2正規形]]（[[部分関数従属]]を排除）
→ [[第3正規形]]（[[推移的関数従属]]を排除）→ [[ボイス・コッド正規形]]

> **1文で判定できる覚え方**
> **第1**：繰り返しをなくす／**第2**：**キーの一部**で決まるものを追い出す／**第3**：**キー以外**で決まるものを追い出す

### (B) キーと制約は「矛盾を入口で防ぐ」ためにある

[[主キー]] ／ [[候補キー]] ／ [[複合キー]] ／ [[外部キー]] ／
[[参照整合性制約]] ／ [[一意性制約]] ／ [[検査制約]] ／ [[NULL]]

> **主キーがNULLを許さない理由**：NULLは「不明」であり、**不明なもので行を識別できない**から。

### (C) SQLは実行順で読むと必ず解ける

> **書く順**：SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY
> **実行順**：**FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY**

[[SELECT文]] ／ [[DDL・DML・DCL]] ／ [[集約関数]] ／ [[GROUP BY句]] ／ [[HAVING句]] ／
[[内部結合]] ／ [[左外部結合]] ／ [[副問合せ]] ／ [[EXISTS述語]] ／ [[ビュー]] ／ [[カーソル]]

### (D) ACIDは「どの仕組みが守るか」まで結びつける

[[ACID特性]]

| 性質 | 守る仕組み |
|---|---|
| 原子性・耐久性 | [[ロールバック]] ／ [[ロールフォワード]] ／ [[チェックポイント]] |
| 独立性 | [[排他制御]]（[[専有ロック]]・[[2相ロッキング]]） |
| 一貫性 | [[参照整合性制約]] などの制約 |

### (E) 同時実行の問題は「何が起きるか」で並べる

[[ロストアップデート]]（更新が消える）／[[ダーティリード]]（未確定を読む）／
[[反復不能読み取り]]（値が変わる）／[[ファントムリード]]（行が増える）
→ 制御するのが [[分離性水準]] ／ [[ロックの粒度]] ／ [[デッドロックの検知]]

### (F) 障害回復は「コミット済みかどうか」で分かれる

```
未コミット   → ロールバック（更新前ログ）   ← 原子性を守る
コミット済み → ロールフォワード（更新後ログ） ← 耐久性を守る
```

[[チェックポイント]] ／ [[ウォームスタート]] ／ [[コミット]]

### (G) 性能の打ち手は層ごとに分かれる

[[インデックス]]・[[B木索引]]（設計）／[[非正規化]]（設計）／
[[実行計画]]（DBMS）／[[ストアドプロシージャ]]（通信量の削減）

### (H) 分析系は「貯める → 掘る → 見せる」の順

[[ETL]]（集める）→ [[データウェアハウス]]（貯める）→ [[データマート]]（切り出す）
→ [[データマイニング]]（掘る）→ [[BIツール]]（見せる）
関連：[[スタースキーマ]] ／ [[ドリルダウン]] ／ [[OLAP]] ／ [[データレイク]]

### (I) 大規模化の技術は「何を諦めるか」で分かれる

[[分散データベース]] ／ [[2相コミット]] ／ [[レプリケーション]] ／ [[シャーディング]] ／
[[NoSQL]] ／ [[ビッグデータ]] ／ [[Hadoop]]

> **NoSQLは関係型より優れているのではありません。**
> **厳密な整合性を少し諦める代わりに、規模の拡張と速度を取る**という取引です。
