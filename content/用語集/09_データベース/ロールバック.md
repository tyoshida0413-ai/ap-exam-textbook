# ロールバック

> **トランザクションを開始前の状態へ巻き戻す処理**。
> **更新前ログ**を使い、[[ACID特性]]の**原子性**を守る。

## 日常のたとえ

書類を書き間違えたとき、修正液で部分的に直すのではなく、**書き始める前の白紙に戻す**のがロールバックです。
中途半端に直した書類を残すより、いったん全部なかったことにするほうが安全だからです。

## なぜそうなるのか

トランザクションが途中で異常終了したとき、そこまでの更新を残してはいけません。
「A口座から引いたが、B口座に足す前に落ちた」という状態を残せば、お金が消えます。

そこでDBMSは、更新のたびに**変更する前の値**をログに書いておき（更新前ログ）、
異常時にはそれを逆順に適用して元に戻します。

### 2つの起こり方

| きっかけ | 説明 |
|---|---|
| **利用者が指示する** | `ROLLBACK` 文を実行する。処理の途中で条件が満たせないと分かったとき |
| **DBMSが行う** | 異常終了・デッドロックの解消・システム障害からの回復のとき |

### セーブポイント

長いトランザクションでは、途中に**セーブポイント**を置き、
そこまで戻す部分的なロールバックもできます（`ROLLBACK TO SAVEPOINT`）。
最初から全部やり直さずに済みます。

### 対になる処理との使い分け

```
未コミット   → ロールバック（更新前ログ）      ← 原子性を守る
コミット済み → ロールフォワード（更新後ログ）  ← 耐久性を守る
```

「**前ログで巻き戻す・後ログで進める**」と唱えて覚えます。

## 混同しやすい語

| 語 | 決定的な違い |
|---|---|
| [[ロールフォワード]] | **コミット済み**を**更新後ログ**で進める。ロールバックは**未コミット**を**更新前ログ**で戻す |
| [[コミット]] | 逆の操作。**確定させる**。コミットした後はロールバックできない |
| [[チェックポイント]] | あちらは復旧の**起点を作る**仕組み。処理そのものではない |

## 試験での問われ方

- 「未コミットのトランザクションが異常終了した場合の回復方法は」→ **ロールバック**（更新前ログ）
- ひっかけ：使うログを入れ替える。**ロールバックは更新前ログ**
- 「コミット済みのトランザクションをロールバックできるか」→ **できない**
