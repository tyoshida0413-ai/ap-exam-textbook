# 副問合せ

> **SQL文の中に入れ子で書くSELECT文**。
> 外側の行の値を使うものを**相関副問合せ**という。

## なぜそうなるのか

「平均給与より高い給与の社員」を出したいとき、平均給与は**先に計算しないと分かりません**。
そこで内側で先に計算します。

```sql
SELECT 氏名 FROM 社員表
WHERE  給与 > (SELECT AVG(給与) FROM 社員表);
```

### 2種類の違いは「実行される回数」

| 種類 | 実行のされ方 |
|---|---|
| 単純な副問合せ | 内側が**先に1回だけ**実行され、その結果を外側が使う |
| 相関副問合せ | 内側が**外側の1行ごとに**繰り返し実行される |

相関副問合せは、**内側から外側の列を参照している**のが見分け方です。

```sql
-- 相関副問合せ：所属部門の平均より給与が高い社員
SELECT 氏名 FROM 社員表 S1
WHERE  給与 > (SELECT AVG(給与) FROM 社員表 S2
               WHERE S2.部門コード = S1.部門コード);   -- 外側のS1を参照
```

外側が1000行あれば内側が1000回動くため、**性能問題の原因になりやすい**という点まで問われます。

### 書ける場所

| 場所 | 呼び名・用途 |
|---|---|
| WHERE句 | 最も一般的。比較・IN・EXISTSと組み合わせる |
| FROM句 | **導出表**（インラインビュー）。副問合せの結果を1つの表として扱う |
| SELECT句 | 1行1列の結果を列として並べる（**スカラ副問合せ**） |

### 組み合わせる述語

| 述語 | 意味 |
|---|---|
| IN | 副問合せの結果の**どれかと一致する** |
| ANY／SOME | 結果の**どれか1つ**と比較が成立する。`> ANY` は最小値より大きい |
| ALL | 結果の**すべて**と比較が成立する。`> ALL` は最大値より大きい |
| [[EXISTS述語]] | 結果が**1行でも存在するか**だけを見る |

> **NOT INの注意**：副問合せの結果にNULLが混ざると、**結果が1件も返らなくなります**
> （→ [[NULL]]）。`NOT EXISTS` に書き換えるのが定石です。

## 混同しやすい語

| 語 | 決定的な違い |
|---|---|
| [[EXISTS述語]] | 副問合せの**使い方の1つ**。存在するかだけを見て、値は取り出さない |
| [[ビュー]] | あちらは**名前を付けて保存する**。副問合せはその場限り |
| [[内部結合]] | 同じ結果を結合でも書ける場合が多い。**結合のほうが速いことが多い**点が問われる |

## 試験での問われ方

- 「外側の値を参照する副問合せは」→ **相関副問合せ**
- 相関副問合せの**実行回数**を答えさせる出題 → 外側の行数だけ実行される
- `> ALL` `> ANY` の意味を問う出題
- SQLを提示して**結果の行数**を答えさせる出題
