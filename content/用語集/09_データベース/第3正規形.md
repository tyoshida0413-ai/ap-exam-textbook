# 第3正規形

> [[第2正規形]]を満たし、さらに**主キー以外の項目によって決まる項目**を分離した状態。
> **推移的関数従属**を取り除いた形。

## 日常のたとえ

名簿に「**社員番号・氏名・部署コード・部署名**」と書いてあるとします。
部署名は、**社員ではなく部署で決まります**。
なのに社員1人ごとに書いているので、部署名を変更すると**その部署の全社員の行を直す**ことになります。

「**その項目は、本当にこの表の主役に属しているのか**」を問い直すのが第3正規形です。

## なぜそうなるのか

### 推移的関数従属とは

```
社員番号 → 部署コード → 部署名
```

社員番号が決まれば部署コードが決まり、部署コードが決まれば部署名が決まります。
つまり部署名は、**主キーから直接ではなく、非キー項目を経由して間接的に**決まっています。
この間接的な決まり方が**推移的関数従属**です。

### 分解の手順

```
【第2正規形の状態】
社員表（社員番号, 氏名, 部署コード, 部署名）
        ↑主キー              ↑この2つの間に 部署コード → 部署名 がある

【第3正規形】
社員表（社員番号, 氏名, 部署コード）
部署表（部署コード, 部署名）        ← 追い出した先。部署コードが主キーになる
```

**部署名を書いている場所が、部署表の1行だけ**になりました。
部署名を変更しても直すのは1か所で済み、社員を全員削除しても部署の情報は残ります。

### 判定の手順（この順で見れば必ず判定できます）

1. 主キー以外の項目を書き出す
2. 「**この項目は、主キー以外の何かで決まらないか**」を1つずつ確認する
3. 決まるものがあれば、**その決める側をキーにした別表**へ追い出す

> **見つけ方のコツ**：**コードと名称がセットで並んでいたら疑う**。
> 「部署コードと部署名」「商品コードと商品名」「都道府県コードと都道府県名」は、
> ほぼ確実に推移的関数従属です。

## 混同しやすい語

| 語 | 決定的な違い |
|---|---|
| [[第2正規形]] | あちらは**主キーの一部**で決まるものを追い出す（[[部分関数従属]]）。第3は**主キー以外**で決まるものを追い出す |
| [[ボイス・コッド正規形]] | 第3正規形をさらに厳密にしたもの。**すべての決定項が候補キー**である状態 |
| [[非正規化]] | 逆方向の操作。**性能のためにあえて重複を戻す** |

## 試験での問われ方

- 「**第3正規形の説明として適切なものはどれか**」
  → **非キー属性間の推移的関数従属が排除されている**
- 科目Bでは「**この表を第3正規形に分解せよ**」と作図させる。
  **関数従属の矢印を書き出してから分解する**のが確実な手順
- ひっかけ：第2正規形の説明（部分関数従属の排除）と入れ替える
