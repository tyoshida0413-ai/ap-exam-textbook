# HAVING句

> [[GROUP BY句]]で作った**グループに対する絞り込み条件**を書く句。
> WHEREは**行**に対して働くのに対し、HAVINGは**グループ**に対して働く。

## 日常のたとえ

名簿を部署ごとの山に分ける作業を考えます。

- **WHERE** ＝ **山に分ける前に、対象外の紙を捨てる**（退職者の紙を先に抜く）
- **HAVING** ＝ **山を作った後で、小さい山ごと捨てる**（3人未満の部署は対象外にする）

**捨てるタイミングが違う**だけですが、結果はまったく変わります。

## なぜそうなるのか

SQLは**書く順と実行される順が違います**。

| 書く順 | SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY |
|---|---|
| **実行順** | **FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY** |

WHEREは**グループ化より前**に実行されるため、**まだグループが存在しません**。
だからWHEREには集約関数（COUNT、AVGなど）を書けません。
HAVINGは**グループ化の後**なので、集約関数を条件に使えます。

```sql
SELECT   部門コード, AVG(給与)
FROM     社員表
WHERE    入社年 < 2022        -- ← 行を絞る（グループ化の前）
GROUP BY 部門コード
HAVING   AVG(給与) >= 300;    -- ← グループを絞る（グループ化の後）
```

この例は「**2022年より前に入社した人だけを対象に**、部門ごとの平均給与を出し、
**平均が300以上の部門だけ**表示する」という意味になります。
WHEREとHAVINGは**どちらか一方ではなく、役割を分けて併用する**のが本来の使い方です。

> **なぜ両方必要なのか**：`HAVING 入社年 < 2022` とは書けません。
> グループ化した後には「入社年」という個々の値がもう残っていないからです。
> 逆に `WHERE AVG(給与) >= 300` とも書けません。まだ平均が計算されていないからです。

## 混同しやすい語

| 語 | 決定的な違い |
|---|---|
| WHERE | **グループ化の前**に、個々の行に対して働く。**集約関数を書けない** |
| [[GROUP BY句]] | あちらは**グループを作る**句。HAVINGは**作られたグループを絞る**句 |

## 試験での問われ方

- 「**WHEREとHAVINGの違いとして適切なものはどれか**」
  → **WHEREは個々の行に、HAVINGはグループ化された結果に適用される**
- SQL文を提示して**結果の行数を答えさせる**問題。
  実行順（FROM → WHERE → GROUP BY → HAVING）で追えば必ず解ける
- ひっかけ：「HAVINGはグループ化の前に適用される」＝**誤り**
