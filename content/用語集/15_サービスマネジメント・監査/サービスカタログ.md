# サービスカタログ

> **現在提供中のサービス**の一覧を、**利用者・顧客が読む形**でまとめた文書。内容・対象者・サービス時間・申込方法・料金などを記載する。計画中や廃止済みまで含む全体は [[サービスポートフォリオ]] であり、**カタログはその一部**にあたる。

## 何を載せるか

| 項目 | 具体例 |
|---|---|
| **サービスの概要** | 経費精算システム。申請から承認、支払データ作成まで |
| **対象となる利用者** | 全社員（承認機能は課長以上） |
| **サービス時間** | 平日 8:00〜20:00 |
| **サポート窓口** | サービスデスク（内線1234・受付は平日9:00〜18:00） |
| **申込方法・提供までの期間** | 所定フォームで申請。アカウント発行は3営業日以内 |
| **料金・費用負担** | 1アカウントあたり月額300円を利用部門に配賦（→ [[チャージバック]]） |
| **関連するサービスレベル** | 応答時間3秒以内、月間稼働率99.5%（→ [[SLA]]） |

## なぜ必要なのか

カタログが無いと、**利用者は「何が使えるのか」「誰に頼めばよいのか」を知る手段がありません**。
結果として、問い合わせが [[サービスデスク]] に集中し、
「そのサービスは提供していません」という応対に時間が費やされます。

もう1つの効果は、**提供側が自分の提供物を把握できる**ことです。
カタログを作る過程で「誰も使っていないのに動き続けているサービス」が見つかることは珍しくありません。
これは [[サービスポートフォリオ]] を使った見直しの入口になります。

**カタログは作って終わりではなく、[[変更管理]] と連動して最新に保ちます。**
サービスの内容や時間が変わったのにカタログが古いままだと、
**書いてあることと実態が違う**という、無いよりたちの悪い状態になります。

## 混同しやすい語

| 語 | 決定的な違い |
|---|---|
| [[サービスポートフォリオ]] | あちらは**計画中・提供中・廃止済みを含む全部**（社内の経営判断用）／こちらは**提供中だけ**（顧客・利用者が見る）。**包含関係を逆にするひっかけが定番** |
| [[SLA]] | あちらは**品質水準を顧客と合意した文書**／こちらは**提供しているサービスの一覧**。カタログにサービスレベルの概要を載せることはあるが、合意そのものではない |
| [[CMDB]] | あちらは**サービスを構成する要素と関係**の記録（技術者が見る）／こちらは**サービスそのものの案内**（利用者が見る） |

## 試験での問われ方

- 「サービスカタログに記載する内容として適切なものはどれか」
  → **提供中の各サービスの概要、サービス時間、利用条件など、利用者が必要とする情報**
- **ひっかけ**：「開発中のサービスを含む全サービスの一覧」→ ✕。それは [[サービスポートフォリオ]]
- **もう1つのひっかけ**：「各サービスを構成するサーバやソフトウェアの一覧」→ ✕。それは [[CMDB]]
