# セキュリティ 混同しやすい語の一覧

> **2つの使い方がある**
> (1) **学習用**：試験で狙われるのは「似た語の取り違え」。ここだけ潰せば失点が大きく減る
> (2) **作業用**：用語集を書くときの設計図（→ 3章の難語リストが執筆の優先順位になる）

---

## 1. 最重要の混同ペア（ここを間違えると失点が大きい）

| 対比 | 決定的な違い | ひっかけの出方 |
|---|---|---|
| [[共通鍵暗号方式]] ↔ [[公開鍵暗号方式]] | 鍵が**同じ**／**別**。鍵数は **n(n−1)/2** 個／**2n** 個 | 100人の鍵数を問う。4,950（共通鍵）と200（公開鍵）を入れ替える |
| **暗号化** ↔ [[ディジタル署名]] | **受信者の公開鍵**で暗号化／**送信者の秘密鍵**で署名 | 鍵の持ち主と向きを入れ替える。**最頻出** |
| [[ディジタル署名]] ↔ [[メッセージ認証符号]] | 公開鍵を使う／**共通鍵**を使う。**否認防止は署名だけ** | 「否認防止ができるのは」→ MACを混ぜる |
| [[ディジタル署名]] ↔ 機密性 | 署名しても**本文は平文のまま**。機密性は得られない | 「署名で確保できるものは」に「機密性」を混ぜる |
| [[ハッシュ関数]] ↔ 暗号化 | **元に戻せない**／戻せる（戻すために暗号化する） | 「ハッシュ化すれば後で復元できる」 |
| [[クロスサイトスクリプティング]] ↔ [[CSRF]] | 情報を**盗む**／操作を**実行させる**。対策も**エスケープ**／**トークン** | 対策を入れ替える |
| [[IDS]] ↔ [[IPS]] | **D**etection＝検知のみ／**P**revention＝**遮断まで**行う | 「遮断するのは」 |
| ファイアウォール ↔ [[WAF]] | **IPとポート**を見る／**HTTPの中身**を見る | 「SQLインジェクションを防げるのは」 |
| [[CSIRT]] ↔ [[SOC]] | **対応・調整**する／**監視・検知**する | 役割を入れ替える |
| [[本人拒否率]] ↔ 他人受入率 | **本人を拒否**する率／**他人を通す**率。**トレードオフ** | しきい値を厳しくしたときどちらが上がるか |
| [[フォールスポジティブ]] ↔ [[フォールスネガティブ]] | 正常を**異常と誤検知**／異常を**見逃す** | 誤検知と検知漏れを入れ替える |
| [[OAuth]] ↔ [[OpenID Connect]] | **認可**（何をしてよいか）／**認証**（誰であるか） | 「OAuthは認証の仕組みである」＝誤り |
| [[CVE]] ↔ [[CWE]] ↔ [[CVSS]] | 個別の**番号**／脆弱性の**種類**／深刻度の**点数** | 3つを入れ替える |
| [[リスク移転]] ↔ [[リスク回避]] ↔ [[リスク保有]] | **保険**／**活動をやめる**／**承知で受け入れる** | 保険を「低減」にする |
| [[パケットフィルタリング]] ↔ [[ステートフルインスペクション]] | 1パケットずつ判断／**通信の文脈**を記憶して判断 | ─ |

## 2. セットで理解すべき語のかたまり

**バラバラに覚えると必ず混ざる。かたまりごと、因果の順で理解する。**

### (A) 暗号の3点セット

```
共通鍵暗号（速い／鍵を渡せない）
公開鍵暗号（鍵を渡せる／遅い）
      ↓ 欠点を打ち消し合う
ハイブリッド暗号 ＝ 鍵だけ公開鍵で渡し、本文は共通鍵で
      ↓ これが実際に動いているのが
SSL/TLS
```

### (B) パスワード保護の攻防

```
ハッシュ化して保存する
   ↓ 攻撃側が対応表を用意 → レインボー攻撃
ソルト（利用者ごとに違う乱数を混ぜる）→ 対応表が無効化される
   ↓ それでも総当たりされる
ストレッチング（何千回も繰り返す）→ 時間的に非現実的にする
```

### (C) メール認証は「必要になった順」で覚える

```
SPF   … 送信元IPをDNSで宣言 → 【弱点】転送されるとIPが変わり失敗する
DKIM  … 電子署名を付ける     → 転送に強い
【両者に共通の穴】検証に失敗したメールをどう扱うか決まっていない
DMARC … 失敗時の処理方針（何もしない/隔離/拒否）を宣言する
```

### (D) PKIの登場人物

```
公開鍵は誰でも配れる → ではその鍵が本物か？
   ↓
認証局(CA)が保証する → ディジタル証明書
   ↓ 期限内に無効化したいとき
CRL（一覧を配る）／ OCSP（都度オンライン照会）
```

### (E) リスク対応の4分類

| 分類 | ひとこと | 例 |
|---|---|---|
| [[リスク低減]] | 起きにくく・被害を小さく | 暗号化、多要素認証 |
| [[リスク回避]] | **そもそもやらない** | サービス廃止 |
| [[リスク移転]] | **誰かに肩代わり** | 保険、外部委託 |
| [[リスク保有]] | **承知で受け入れる** | 影響が軽微で対策費が上回る |

### (F) DNSを悪用する攻撃

| 語 | 何をする | 対策 |
|---|---|---|
| [[DNSキャッシュポイズニング]] | 偽の名前解決を覚え込ませる | [[DNSSEC]] |
| [[ファーミング]] | 上記の結果、正規URLでも偽サイトへ | 同上 |
| [[DNSリフレクタ攻撃]] | 送信元を偽装し、**大きな応答**を標的へ集中 | 外部からの再帰問合せを止める |

## 3. 難語リスト（フェーズ3のレビュー対象）

**138語中、次の35語を「難」とする。** 残り103語は「易」。
判定基準は `00_引き継ぎ_用語集.md` の6章に従う。

| 語 | なぜ難しいか |

### 易（103語）— 定義を膨らませれば足りる

制度・組織・規格名（[[NISC]] [[ISMAP]] [[PCI DSS]] [[JPCERT-CC]] [[J-CRAT]] [[プライバシーマーク]] [[CVE]] [[CWE]] [[ISO-IEC 15408]]）、
個別のマルウェア・攻撃名（[[トロイの木馬]] [[スパイウェア]] [[ルートキット]] [[ランサムウェア]] ほか）、
個別の製品・機能（[[UTM]] [[DLP]] [[EDR]] [[SIEM]] [[TPM]] [[MDM]] ほか）など。
