# CSIRT

> Computer Security Incident Response Team。セキュリティインシデントに対応する専門組織。検知後の分析・封じ込め・復旧・再発防止までを担う。

## 日常のたとえ

**消防隊**です。火事（インシデント）が起きたら出動し、初期消火・被害拡大の防止・鎮火後の原因調査までを担います。
普段から街を巡回して火の元をチェックする「見回り担当」（[[SOC]]）とは役割が異なります。

見回り担当が「火の気があるぞ」と通報して初めて消防隊が動き出すように、
CSIRTも自分から常時監視をしているわけではなく、**異常の一報を受けてから本領を発揮する**組織です。

## なぜそうなるのか

CSIRTは、セキュリティインシデントが発生した際の**対応の司令塔**です。
インシデント対応は一般に次のフェーズで進みます。

```
準備 → 検知・分析 → 封じ込め・根絶・復旧 → 事後対応（教訓の反映）
```

なぜ「専門チーム」として独立させる必要があるかというと、インシデント対応は
**技術的な調査（どこまで被害が及んだか）**と**組織的な調整（誰にいつ何を報告するか）**の
両方を同時にこなす必要があり、片手間の担当者では対応が遅れ被害が広がるからです。

CSIRTはこの一連のプロセスを主導し、**社内外の関係者との調整**も担います。
（例：経営層への報告、広報対応、外部機関との連携、必要に応じて[[JPCERT-CC|JPCERT/CC]]への相談）

**「監視して見つける」役割はSOCが担い、「見つかった後にどう動くか」をCSIRTが担う**、
という役割分担で理解すると整理しやすくなります。SOCからの一報を受けて、
CSIRTが被害範囲の特定・関係部署への連絡・復旧作業の指揮を行う、という流れです。

## 混同しやすい語

| 語 | 決定的な違い |
|---|---|
| [[SOC]] | SOCは**監視・検知**（ログを24時間見張る）。CSIRTは**対応・調整**（見つかった後に動く）。試験で最も入れ替えられやすいペア |
| [[JPCERT-CC\|JPCERT/CC]] | CSIRTは**組織内**のインシデント対応チーム。JPCERT/CCは**国内外の調整役**を担う代表的なCSIRT（社会全体でみると「CSIRTの一種」にあたる） |

## 試験での問われ方

- 「CSIRTの役割として適切なものは」→ **インシデント発生時の対応方針を決定し、外部機関と調整する**
- 「セキュリティ機器のログを常時監視し、脅威を検知する」という選択肢は**SOC**の説明であり誤り
- CSIRTとSOCを入れ替えた選択肢、JPCERT/CCとの関係を問う設問が頻出
