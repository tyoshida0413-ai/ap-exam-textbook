# レインボー攻撃

> ハッシュ値と平文パスワードの対応表（レインボーテーブル）を事前に用意し、盗んだハッシュ値から高速に元のパスワードを割り出す攻撃。[[ソルト]]で防ぐ。

## 日常のたとえ

**「よくある印鑑の押し跡見本帳」のようなものです。**
よく使われる印鑑（パスワード）の押し跡（ハッシュ値）を事前に集めて見本帳を作っておけば、
盗んだ押し跡と見本帳を照合するだけで、**押した印鑑（元のパスワード）が瞬時に分かります**。

## なぜそうなるのか

まともなシステムはパスワードを平文で保存せず、[[ハッシュ関数]]で変換してから保存します。
データベースが盗まれても、そこにあるのは意味不明な文字列だけ ── のはずでした。

ところが攻撃者は考えました。「よく使われるパスワードを片っ端から変換して、**対応表を作っておけばいい**」と。

```
password  →  5f4dcc3b5aa765d61d8327deb882cf99
123456    →  e10adc3949ba59abbe56e057f20f883e
```

この対応表（レインボーテーブル）があれば、盗んだハッシュ値と照合するだけで
**元のパスワードを瞬時に特定**できます。1件ずつ計算し直す必要がないため、通常の総当たりより高速です。

## 混同しやすい語

| 語 | 決定的な違い |
|---|---|
| [[ブルートフォース攻撃]] | ブルートフォースは**その場で1件ずつ計算**する。レインボー攻撃は**事前に作った対応表を引く**だけなので圧倒的に速い |
| [[ソルト]]（対策） | 利用者ごとに異なる乱数を混ぜることで、**同じパスワードでも保存値がバラバラになり**、事前に作った対応表が一致しなくなる＝無効化される |

## 試験での問われ方

- 「レインボー攻撃を防ぐための対策として適切なものは」→ **ソルトを付加する**
- 「レインボーテーブル攻撃の説明として適切なものは」→ 事前に作成したハッシュ値と平文の対応表を用いる攻撃
