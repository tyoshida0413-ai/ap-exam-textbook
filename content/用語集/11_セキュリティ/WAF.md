# WAF

> Web Application Firewall。Webアプリケーションへの通信内容（HTTPの中身）を検査して攻撃を遮断する仕組み。

## 日常のたとえ

**荷物のX線検査**です。ファイアウォールが「誰が、どの入口から入るか」だけを見る**門番**だとすると、
WAFは「**持ち物の中身**」まで見る検査官です。門番を通過しても、中身が危険物なら止められます。

## なぜそうなるのか

### なぜファイアウォールだけでは足りないのか

ファイアウォールは「**どこから来て、どの入口へ向かうか**」（IPアドレスとポート番号）しか見ません。
Webサイトを公開している以上、80番・443番という入口は開けておくしかありません（閉じたらサイトが見られない）。

[[SQLインジェクション]]のような攻撃は、**まさにその正規の入口から、正規の見た目で**入ってきます。
中身が攻撃だとしても、ファイアウォールは中身を見ないので**素通り**させてしまいます。

### WAFが見ているもの

WAFは**HTTPの通信内容**（リクエストの中身）を検査します。
「入力欄にSQL文の断片が混ざっていないか」「スクリプトタグが含まれていないか」といった
**アプリケーション層の異常**を検知し、遮断します。

```
「FWはIPアドレスとポート番号で制御しており、HTTP通信の内容までは検査しないため。」
```

これが「なぜファイアウォールだけでは防げないか」の記述式解答の型です。

## 混同しやすい語

| 語 | 決定的な違い |
|---|---|
| ファイアウォール | ファイアウォールは**IPアドレス・ポート番号**（ネットワーク層〜トランスポート層）を見る。WAFは**HTTPの中身**（アプリケーション層）を見る |
| [[IDS]] / [[IPS]] | IDS/IPSは通信全般の不審な挙動を検知・遮断する汎用的な仕組み。WAFは**Webアプリケーションに特化**して、SQLインジェクションやXSSのようなアプリケーション層の攻撃を検査する |

## 試験での問われ方

- 「WAFの導入によって防御できる攻撃として適切なものは」→ **SQLインジェクション**（ポートスキャンやARPスプーフィングはネットワーク層の話で誤り）
- 「ファイアウォールでこの攻撃を防げなかった理由を述べよ」（記述式）→ IPとポートのみの検査で、HTTP本文を見ていないため
