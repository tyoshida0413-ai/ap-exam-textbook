### TODO-1：高解像度モニターで本文が広がらない

**症状（2026-08-02時点）**：画面を広げても本文が930pxのまま。余った空間がすべて余白として捨てられる。

**2026-08-02の原因分析は誤りだった。** 当初は「`base.scss` の `.page{max-width:calc(1200px+300px)}`＝1500pxで頭打ち」と推測したが、
2026-08-03にヘッドレスChrome+CDPの `CSS.getMatchedStylesForNode` で実際に勝っているルールを確認したところ、**全く別の原因**だった。

**真因（2026-08-03 CDP実測で確定）**：
`@quartz-themes/core`（`node_modules/@quartz-themes/core/dist/index.js`）が `(min-width:1200px)` で
以下を**unlayered**（`@layer` に属さない）で注入している。

```css
/* @quartz-themes/core のCSS（コメントも原文どおり） */
div#quartz-root.page {
  /* workaround for reader-mode */
  display: grid;
  place-items: center;
  width: 100%;
  min-width: 100dvw;
  max-width: 100dvw;   /* ← .pageは常に画面幅いっぱい。custom.scssの max-width:1920px は無意味だった */
  padding: 0;
  margin: 0;
}
div#quartz-root.page div#quartz-body {
  width: min(100%, calc(1200px + 300px));      /* ← 本当の頭打ちはこっち。1500px */
  max-width: min(100%, calc(1200px + 300px));
  padding: 0 auto;
}
```

CSSのカスケードレイヤー仕様上、unlayeredなルールはlayered（`@layer quartz-base`内）のルールに常に勝つ。
`custom.scss` の出力もunlayeredだが、セレクタの詳細度で負けていた：
`.page`（詳細度 0,1,0）< `div#quartz-root.page`（id1つ分＝1,1,1）。
`#quartz-body` 側も同様に、こちらの `.page > #quartz-body{grid-template-columns:...}`（詳細度 0,2,0）が
`div#quartz-root.page div#quartz-body{max-width:min(100%,1500px)}`（詳細度 2,1,2）に負けていた。
**「本文の横幅を広げる」セクションは、書かれた当初から一度も効いていなかった。**

**決定済みの方針（ユーザー選択・変更なし）**：
> **画面幅に応じて可変・上限1400px**

**実装内容（2026-08-03・`quartz/styles/custom.scss` セクション1を全面書き換え）**：
[[00_引き継ぎ]] の罠#6と同じ「詳細度を上げて上書きする」パターンで、本当の頭打ち元である `#quartz-body` 側を、
同等以上の詳細度（`body` を前置）で上書きした。

```scss
$sidePanelWidthNarrow: 280px;

@media all and #{$desktop} {
  .page > #quartz-body {
    grid-template-columns: #{$sidePanelWidthNarrow} auto #{$sidePanelWidthNarrow};
  }

  body div#quartz-root.page div#quartz-body {
    width: min(100%, calc(1400px + #{$sidePanelWidthNarrow} * 2 + 10px));       // = min(100%, 1970px)
    max-width: min(100%, calc(1400px + #{$sidePanelWidthNarrow} * 2 + 10px));
  }
}
```

**検証結果（2026-08-03、CDP実測・`Emulation.setDeviceMetricsOverride` + `getBoundingClientRect`）**：

| 画面幅 | #quartz-body幅 | 本文（center）幅 | 判定 |
|---:|---:|---:|---|
| 1440 | 1440（可変） | 870 | ✅ 可変域 |
| 1920 | 1920（可変） | 1350 | ✅ 可変域 |
| 2560 | 1970（頭打ち） | **1400** | ✅ 上限どおり |
| 2810 | 1970（頭打ち） | **1400** | ✅ 上限どおり |
| 3440 | 1970（頭打ち） | **1400** | ✅ 上限どおり |
| 600〜1199（モバイル・タブレット） | 変更前と同じ | 変更前と同じ | ✅ 回帰なし（`@media $desktop` の外なので無変更） |

スクリーンショットでも崩れなし（左右サイドバー280px・グラフ/目次/バックリンクの表示は変更前と同一）。

### TODO-2：用語クリックでサイドパネルに用語ページを表示（Stacked Pages）

**ユーザーの要望**：「用語をクリックしたときに、サイドパネルに当該用語のページを表示させる」

**実装（2026-08-03）**：`quartz.config.yaml` の `@quartz-community/stacked-pages` を `enabled: true` にし、
ドキュメント記載の既定オプション（`maxTabs:8` / `mobileBreakpoint:800` / `showSpines:true` / `animateTransitions:true`）を明記した。
プラグイン本体は**既にインストール済み**だった（2026-08-02時点の「本体未インストール」というメモは誤り。`node_modules/@quartz-community/stacked-pages` に実体あり）。

**実際の挙動（CDPでクリックを実際にシミュレートして確認。ドキュメントの説明とは細部が異なる）**：
- 内部リンクをクリックすると、Quartz標準のSPAルータ（`window.spaNavigate`）で**通常どおりページ遷移**する
  （ドキュメントにある「遷移せず横に並べて開く」ような複数ページ同時表示ではない）
- 遷移後、`document.addEventListener("nav", ...)` で発火する更新処理が、画面端に固定表示の
  **「バインダー」帯**（`#stacked-pages-container.binder-active`、`position:fixed; inset:0` の全画面オーバーレイ内に
  幅40pxの `.binder-strip-left`）を作り、訪問したページを縦書きタブとして積み上げる
- タブをクリックすると該当ページへ`spaNavigate`で戻る、×ボタンでタブを閉じられる
- `body` に `has-binder-left` / `has-binder-right` クラスが付く。800px未満では `display:none` で自動的に無効（確認済み）

**⚠️ 有効化しただけでは左サイドバーと重なるバグがあった（2026-08-03 発見・修正済み）**：
プラグイン本来の設計は `body.has-binder-left .page { padding-left: 40px }` で本文を40px退避させるものだが、
TODO-1と全く同じ原因（`@quartz-themes/core` の `div#quartz-root.page{padding:0}` がidの詳細度で勝つ）でこの退避が無効化されており、
`#quartz-body` が画面幅いっぱいになる範囲（およそ1200〜1970px＝1440pxや1920pxなど一般的な解像度を含む）では、
40px幅のバインダー帯が左サイドバー（エクスプローラー）の文字にそのまま重なって読めなくなっていた
（`.page` 側で退避が効かないのはTODO-1と同根の問題）。

**対処（`custom.scss` にセクション4として追記）**：`.page` 側の詳細度勝負を避け、サイドバー自身の内側に余白を作る方式にした。

```scss
body.has-binder-left .sidebar.left {
  padding-left: calc(2rem + 40px);
}
body.has-binder-right .sidebar.right {
  padding-right: calc(2rem + 40px);
}
```

## 2.9 用語サイドパネル（TODO-2の作り直し・2026-08-03 設計確定）

> **これがTODO-2の正式な実装方針。** 本ファイルのstacked-pagesは要望を満たさないため破棄し、自作する。
> ユーザー承認済みの設計。

### 満たすべき要件（ユーザーの言葉）

> 「教科書を読みながら、わからない用語が右に表示されて**読み進められる**」
> 「それぞれが**独立**していないと意味がない」
> 「画面外をクリックしたことで閉じてしまうような仕様は**問題外**」

**つまり教科書とパネルは同時に生きていること**が要件の核心。片方を触るともう片方が閉じる／隠れる実装は不可。

### 実装方式：ホバープレビュー（popover）と同じ仕組みを流用する

Quartzのpopoverは既に「ページをfetchして `.popover-hint` を取り出して表示」しており、必要な処理が揃っている。

- `.popover-hint` は**タイトル部の`div`と本文の`<article>`の両方**に付いている（＝用語ページの中身が丸ごと取れる）
- `fetchCanonical()` は**alias用の空リダイレクトページを自動追跡して実体へ到達する**（[[00_引き継ぎ]] の罠#8の問題が原理的に起きない）
- `normalizeRelativeURLs()` で取得先ページの相対リンクを正しく張り直せる

### レイアウト設計（幅の問題をどう解いたか）

当初「右端にオーバーレイ」で提案したが、**1440pxでは本文を約200px覆うため成立しない**と実測で判明（用語ページは表を含むため最低450px前後必要で、本文を覆わずに重ねる余地がない）。
ユーザー提案により、**左サイドバー（エクスプローラー）を畳めるようにする**ことで解決した。

パネルはオーバーレイではなく**グリッドの1列**として組み込み、右サイドバーの枠を引き継ぐ。

| 画面幅 | 現在（パネルなし） | パネル＋左そのまま | **パネル＋左を畳む** |
|---:|---:|---:|---:|
| 1440 | 870px | 670px | **955px** |
| 1920 | 1350px | 1150px | **1400px** |
| 2560 | 1400px | 1400px | **1400px** |
| 3440 | 1400px | 1400px | **1400px** |

→ **左を畳めば、パネルを開いても本文は現在より広い**（1440pxで870→955px）。

### 動作仕様

**左サイドバーの開閉**
- 畳む／戻すボタンを常時設置。パネルとは無関係に手動で切り替える
- 状態は localStorage に保存し次回も維持
- **自動では畳まない**（勝手に動くと戸惑うため）

**サイドパネル**
- **本文（`article`）内の内部リンクのみ**をパネルで開く。パンくず・エクスプローラー・目次・バックリンクは従来どおり遷移する（区別しないと「Home」までパネルで開いてしまう）
- 開いてもURLは変わらず、本文もスクロール位置も動かない
- パネル内のリンクをクリックするとパネルの中身が差し替わる（本文は動かない）
- **閉じるのは × ボタンと Esc のみ。画面外クリックでは閉じない**（要件）
- Ctrl・Cmd・中クリックは横取りせず、新しいタブで開く
- 800px未満では無効化し通常遷移
- パネルを開いている間、グラフビュー・目次・バックリンクは隠れる（閉じれば復帰）

**意図的に作らないもの（YAGNI）**：タブ、戻る履歴、複数パネルの同時表示

| `quartz/components/scripts/sidepanel.inline.ts` | 新規・パネル本体 |

併せて `stacked-pages` を `enabled: false` に戻し、不要になる `custom.scss` セクション4（バインダー帯の余白対策）を削除する。

### 検証項目（前回の失敗を踏まえ必須）

- 教科書→用語リンクのクリックでパネルが開き、**URLが変わらない**こと
- **教科書とパネルが独立して**スクロール・クリックできること（要件の核心）
- パネル内リンクで中身が差し替わること
- Esc / × で閉じ、**画面外クリックでは閉じない**こと
- Ctrl+クリックが壊れていないこと
- 左サイドバーの開閉が効き、リロード後も維持されること
- **4段階遷移（Home→用語集→11_セキュリティ→機密性）** で破綻しないこと ← 前回これを飛ばして事故った
- 1440 / 1920 / 3440px、**ライト・ダーク両方**でスクリーンショット確認

## 2.10 付箋（しおり）機能 ＋ 端末間同期（2026-08-04 実装・**デプロイ済み**）

### 解こうとした問題
教科書1ページが13万字級（10_ネットワークは132KB）あり、途中で中断すると
「どこまで読んだか」を見失って最初から読み直しになる。

### 仕様
- **右下に常設のボタン2つ**：🔖（今の位置に付箋を貼る／剥がす）と ≡（付箋の一覧）
- **1ページにつき付箋は1つ**。貼り直すと位置が更新される（同じ位置で再度押すと剥がれる）
- **位置は「直近の見出しのid」で覚える**。スクロール量(px)で覚えると、本文を1文字加筆しただけで狂う
- **一覧はどのページからでも開ける**。クリックで別ページの続きへ直行（要件の核心）
- **付箋のあるページを開くと「前回の続き（見出し名）から読む」バナー**が本文の真上に出る
- **端末間同期**：Cloudflare Worker + KV。設定しなければ従来どおり端末内だけで完結する

### 実装ファイル
| ファイル | 内容 |
|---|---|
| `quartz/components/scripts/bookmark.inline.ts` | 新規・本体（付箋・一覧・バナー・同期） |
| `quartz/components/styles/bookmark.scss` | 新規・見た目 |
| `quartz/plugins/emitters/componentResources.ts` | スクリプト注入（サイドパネルと同じ場所） |
| `quartz/styles/custom.scss` | `bookmark.scss` を `@use`（**[[00_引き継ぎ]] の罠#15**。componentResources.css に渡すと負ける） |
| `sync-worker/worker.js` ほか | 新規・同期API（**手動デプロイ**。手順は同ディレクトリのREADME） |

### 検証（CDP実測・計36項目すべて合格）
機能18項目（貼る／剥がす／位置更新／一覧移動／バナー／モバイル390px／既存機能の非破壊）＋
同期18項目（Worker単体の拒否系／2端末の往復／墓標／衝突解決／オフライン耐性）。
本番URLでも動作を確認済み。

### 実装中に踏んだ罠（→ [[00_引き継ぎ]] の罠#26〜#29 に記録）
1. **バナーを消す順番**でスクロール位置が74pxずれた
2. **HTTPヘッダーに日本語を入れると fetch が例外**を投げ、同期が丸ごと動かない
3. **`location.pathname` の表記揺れ**で同じページが別ページ扱いになり、端末間で付箋が二重化しうる
4. **削除をレコード削除で実装すると、他端末から復活する**（墓標が要る）

1ページに複数の付箋／タグ・メモの付与／読了率の可視化／ログイン機能
