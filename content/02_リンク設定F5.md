## 2.6 教科書→用語集のリンク設定【F5】（用語集の完成後に行う）

### なぜやるのか

用語集の各ファイルは教科書へリンクしている（用語集→教科書：140本）。
しかし**教科書から用語集へのリンクは、作った直後は0本**である。
理由は制作順で、教科書を書いた時点では用語集がまだ存在しないため。

このままだと**片道**になり、「教科書を読んでいて分からない語があっても用語集へ飛べない」。
[[00_引き継ぎ]] の1章に掲げた「**教科書と相互に行き来できる網**」が成立しないので、
**用語集がその分野で完成したら、必ずこの作業を行う**。

### 粒度のルール（2026-08-02 実測にもとづき決定）

> ## ✅ **段落ごとに初出1回だけリンクする。表の中も対象にする。**

セキュリティ（36,800字・用語140語）での実測値：

| 粒度 | リンク数 | 判定 |
|---|---:|---|
| 節ごと初出（表を除く） | 58 | 少なすぎる。辞書として機能しない |
| 段落ごと初出（表を除く） | 71 | まだ少ない |
| 節ごと初出（表を含む） | 124 | ─ |
| **段落ごと初出（表を含む）** | **164** | **← これを採用** |
| 全出現をリンク | 352 | 多すぎる。本文がリンクだらけで読めない |

**「段落」の定義**：空行で区切られたかたまり。同じ段落内に同じ語が2回出たら、**最初の1回だけ**リンクする。

### ⚠️ 表の中も必ずリンクする（当初の判断を実測で覆した経緯）

当初は「表の中はリンクしない」と決めかけたが、**これは誤り**だったので撤回した。

- 教科書は**比較表が主役**の構成で、用語の出現352回のうち**97回が表の中**にあった
- 表を除外すると、`IDS`↔`IPS`、`CVE`↔`CWE`↔`CVSS` のような
  **最も引きたくなる対比表からリンクが消える**。辞書として使えなくなる
- 除外しようとした理由は「レイアウト崩れの懸念」だったが、
  **用語集の混同ペア表では既に表内リンクを使っており、公開サイトで正常表示されている**。懸念は成り立たない

### リンクしない場所（除外）

| 場所 | 理由 |
|---|---|
| **見出し行**（`#` で始まる行） | 見出しがリンクだらけになると構造が読めない |
| **コードブロック**（``` で囲まれた範囲） | 図解・ASCIIアートが崩れる |
| **付録すべて**（`## 付録A` 以降） | 特に**付録A 用語チェックリスト**は想起用。リンクがあると答えが見えてしまう。付録B想定問題・付録Cプロンプト集も対象外 |

セキュリティでは、付録に130回の出現があったが、これらはすべて除外した。

### 表記ゆれの扱い

> **厳密にしすぎない。同じものは同じ語として扱い、用語集のファイルは増やさない。**

- 例：**ディジタル署名／デジタル署名** は同一。ファイルは1つだけ作る
- 吸収の方法：用語集ファイルの frontmatter `aliases:` に別表記を書く
  ```yaml
  ---
  title: ディジタル署名
  aliases:
    - デジタル署名
  ---
  ```
- リンクを張るときは `[[ディジタル署名]]` に統一してよい。
  本文の表記を保ちたい場合は `[[ディジタル署名|デジタル署名]]` を使う
- **表記ゆれのたびに新しいファイルを作らない**（語数が無意味に増え、内容も重複する）

### ⚠️ リンクターゲットは必ず「実ファイル名」にする（2026-08-02 実測で発覚した重大な罠）

**当初の実装は失敗した。** `[[表記そのまま]]`で置換すると、次の2つが同時に壊れる。

1. **aliasでリンクすると、ホバープレビューの中身が空になる**
   `[[デジタル署名]]`（実ファイルは`ディジタル署名.md`、`デジタル署名`はalias）と書くと、
   Quartzは`alias-redirects`プラグインにより**`meta http-equiv="refresh"`だけの空リダイレクトページ**を
   ルート直下に自動生成し、リンクはそこを指す。**クリックすれば最終的に正しいページへ着くので
   リンク切れ検査（href実体突合）ではすり抜けてしまう**が、ホバー時にfetchされる中身は
   `<meta http-equiv="refresh">`のみで、辞書の核心である**ホバープレビューが機能しない**。
   （CDPで実測：`article.popover-hint`が存在せず、ポップオーバーに何も表示されないことを確認済み）

2. **titleに`/`を含む語（ISO/IEC 15408、JPCERT/CC、S/MIME）で、[[00_引き継ぎ]] の3章と同じスラッシュ問題が再発する**
   `/`が実ファイル名では`-`に置換されている（`ISO-IEC 15408.md`）のに、
   titleの表記のまま`[[ISO/IEC 15408]]`と書くと`iso/iec-15408`という存在しないパスを指す。

**正しい実装**：リンクターゲットは常に**用語集ファイルのbasename（拡張子を除いたファイル名）**にし、
表記がbasenameと異なる場合（alias・別表記）だけ`[[basename|見つかった表記]]`にする。

### 実行手順

**担当モデル：Sonnet**（→ 2.7）

1. 対象分野の用語一覧を、**「ファイル名(basename)」→「title・aliasesの全表記」**の形で取得する
   （表記だけを集めてリンクターゲットにしてはいけない。ファイル名を主キーにする）
2. **長い語から順に**処理する（`公開鍵暗号方式` を先に処理しないと `公開鍵` が誤爆する）
3. 上記ルールで `[[basename]]` または `[[basename|表記]]` に置換する
4. **検証**（→ 下記4項目。特に(4)は必須）

参考実装（実行後は必ず4の検証を行うこと。ファイル名を主キーにしている点が最重要）：

```bash
cd "/Users/yoshidatomohiro/Library/Mobile Documents/iCloud~md~obsidian/Documents/second_brain/002.Notes/002.Privates/勉強/応用情報技術者試験"
python3 - <<'PY'
import re, glob, os
FIELD = "11_セキュリティ"          # ← 対象分野に変える
BOOK  = f"教科書/{FIELD}.md"

# term_to_slug: 表記(title自身 or alias) -> 実ファイル名(=正しいリンクターゲット)
term_to_slug = {}
for f in glob.glob(f"用語集/{FIELD}/*.md"):
    base = os.path.splitext(os.path.basename(f))[0]   # ★ 実ファイル名を主キーにする
    if base.startswith("00_"): continue
    fm = open(f, encoding='utf-8').read().split('---')[1]
    title=None; aliases=[]; in_aliases=False
    for line in fm.split('\n'):
        if line.startswith('title:'): title=line[6:].strip()
        elif line.startswith('aliases:'): in_aliases=True
        elif line.startswith('  - ') and in_aliases: aliases.append(line[4:].strip())
        elif line and not line.startswith(' '): in_aliases=False
    if title:
        term_to_slug[title] = base
        for a in aliases: term_to_slug[a] = base

terms = sorted(term_to_slug.keys(), key=len, reverse=True)   # 長い語から（誤爆防止）

src = open(BOOK, encoding='utf-8').read().split('\n')
appendix = next((i for i, l in enumerate(src) if l.startswith('## 付録')), len(src))

out=[]; infence=False; para=0; prev_blank=True; seen=set()
for i, l in enumerate(src):
    if l.strip().startswith('```'): infence=not infence; out.append(l); continue
    if l.strip()=='': prev_blank=True; out.append(l); continue
    if prev_blank: para+=1
    prev_blank=False
    if i>=appendix or infence or l.startswith('#'):
        out.append(l); continue            # 付録・コード・見出しは除外（表は対象）
    for t in terms:
        slug = term_to_slug[t]
        k=(slug, para)                      # ★ 実ファイル名単位で重複判定（表記違いでも同一ページなら1回）
        if k in seen: continue
        parts=re.split(r'(\[\[[^\]]*\]\])', l)
        done=False
        for j,p in enumerate(parts):
            if p.startswith('[['): continue
            if t in p:
                repl = f'[[{slug}]]' if t==slug else f'[[{slug}|{t}]]'   # ★ 表示は元の表記のまま
                parts[j]=p.replace(t, repl, 1); done=True; break
        if done:
            l=''.join(parts); seen.add(k)
    out.append(l)
open(BOOK,'w',encoding='utf-8').write('\n'.join(out))
print(f"リンク設定完了: {len(seen)} 箇所")
PY
```

### 検証（必須）

```bash
# (1) リンク数が想定の範囲か
grep -o '\[\[[^]]*\]\]' 教科書/<分野>.md | wc -l

# (2) 見出し・コードブロック・付録に混入していないか
grep -n '^#.*\[\[' 教科書/<分野>.md          # 見出しに入っていたらNG
awk '/^## 付録/{f=1} f && /\[\[/{print NR": "$0}' 教科書/<分野>.md   # 付録に入っていたらNG

# (3) 入れ子の壊れがないか（[[[[ や ]]]] が無いこと）
grep -n '\[\[\[\|\]\]\]' 教科書/<分野>.md

# (4) リンク切れ検査（[[00_引き継ぎ]] の9章の href 突合コマンドを教科書にも適用する）

# (5) ★最重要：aliasリンクが実体ページを指しているか（href実体突合だけでは検出できない）
grep -o '<a[^>]*>[^<]*</a>' 教科書/<分野>.html | grep 'alias' | head -20
# → href が "../用語集/<分野>/xxx" のように用語集フォルダを経由していればOK
# → href が "../xxx"（用語集フォルダを経由しない）だった場合、alias-redirects の空リダイレクトを
#   踏んでいる。ホバープレビューが機能しないので、実行手順のスクリプトが正しく動いていない
```

### ★ (6) F5後マークダウン検証（2026-08-02 に見落として実害が出た）

**リンクを入れるとマークダウンが壊れる。** リンク数やリンク切れをいくら確認しても検出できない。
**ビルド後のHTMLに記法が literal で残っていないか**を必ず確認する。

```bash
# 描画結果に [[ や ** が生テキストで残っていたら壊れている
cd "<Quartzのpublic>"
python3 -c "
import re,html
h=open('教科書/<分野>.html',encoding='utf-8').read()
m=re.search(r'<article.*?</article>',h,re.S)
b=html.unescape(re.sub(r'<[^>]+>','',m.group()))
print(\"literal '[[' :\", b.count('[['))
print(\"literal '**' :\", b.count('**'))
"
# → いずれも 0 でなければ壊れている

# 内容が消えていないかもF5前のバックアップと照合する（実行前に必ずcpを取る）
```

**壊れる3パターンと対処**：

| パターン | 何が起きるか | 対処 |
|---|---|---|
| 表の中の `[[a\|b]]` | `\|` が**セル区切り**と解釈され表が崩壊する | 表の行では `\|` を `\\\|` にエスケープする |
| `**[[語]]**` | 太字の中身がリンクだけ。CJK文脈で `**` がliteral化 | 外側の `**` を外す（リンク自体が十分目立つ） |
| `**前置き[[語]]**` / `**[[語]]後続**` | 太字の**境界にリンクが接する**とliteral化 | リンクを太字の外に出す（`**前置き**[[語]]`） |

> **なぜ起きるか**：CommonMarkの emphasis は「左/右フランキング」条件で判定される。
> 閉じ `**` の直前が `]` や全角の `）` のような**約物**だと右フランキング条件を満たさず、
> 太字として解釈されずに `**` がそのまま表示される。日本語文書で特に起きやすい。

**(4)(5)(6) は必ず行う。** (4)だけでは、alias-redirectsが自動生成する「実体を持つがほぼ空のリダイレクトページ」
を**リンク切れとして検出できない**（実ファイルとしては存在するため）。
2026-08-02の作業で、当初の実装がこの罠にはまり、`[[デジタル署名]]`（alias）のようなリンクが
**クリックすれば正しいページへ着くのにホバーでは何も表示されない**という不具合を作り込んだ。
(4)は「リンク切れではない」ことしか確認できず、「ホバーが機能するか」は別に確認する必要がある。

## 2.7 リンク設定はどのモデルでやるか

> **Sonnetで十分。**

- リンク先は**既に確定している**（用語集のファイル群）。設計判断が要らない
- やることは「本文中の語を `[[ ]]` で囲む」**機械的な作業**
- 正誤が**機械的に検証できる**（上記の検証コマンド）
- 手本もある（用語集→教科書のリンク方式）

用語集F2（Sonnetで成功した量産作業）と同じ性質。
**ただしルール（粒度・除外・表記ゆれ）はこの本ファイルで確定済みであることが前提。**
ルールが未確定のまま渡すと、リンクだらけの読みにくい教科書になる。
