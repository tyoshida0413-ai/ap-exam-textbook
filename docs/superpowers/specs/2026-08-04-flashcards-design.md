# 用語集フラッシュカード機能 設計書

作成日：2026-08-04
対象リポジトリ：`tyoshida0413-ai/ap-exam-textbook`（ブランチ `v5`）

## 目的

応用情報技術者試験の用語集（323語）を、ブラウザ上でそのまま暗記練習できるようにする。
サイトのリンクを1回クリックすれば学習が始まる状態にし、外部サービスへのログインや別アプリの操作を挟まない。

## 背景と経緯

当初 NotebookLM のフラッシュカード機能を検討したが、以下の理由で自作に切り替えた。

- 共有リンクの到達先がノートブック画面であり、そこから利用者が手動でフラッシュカードを選ぶ2ステップになる（実機確認済み）
- 生成枚数を制御できない。API の `flashcard_count` は実測値と一致せず（表示9件に対し実体128件）、指示による網羅も保証されない
- 出力言語を指定するパラメータが無く、日本語化はプロンプト頼みで不安定（英語128枚／日本語83枚と試行ごとに変動）

Anki 連携も検討したが、AnkiWeb はログインを挟み、`.apkg` 配布はダウンロードとアプリ操作を挟むため、目的の「ワンクリックで学習開始」を満たさない。

## 前提の実測結果

設計時に用語集323ファイル全件を機械的に検査した。

| 検査項目 | 結果 |
|---|---|
| 総ファイル数 | 323（データベース77／ネットワーク105／セキュリティ141） |
| うち索引ページ `00_混同しやすい語の一覧.md` | 3件。用語ではないためカード化から除外し、**カードは320枚**（76／104／140）となる |
| frontmatter に `title` がある | 323 / 323 |
| H1見出しの直後が blockquote である | 323 / 323 |
| `title` の重複 | 0件（カテゴリ振り分けが一意に定まる） |
| 定義文が複数行の blockquote | 128件（結合が必要） |
| 定義文に含まれる wikilink | 62件。すべて `[[単純形]]`。パイプ記法・見出し付きは0件 |
| 定義文の文字数 | 最小22／中央値43／最大163 |
| 定義文に答え（title または alias）が露出 | **19件**（対策が必要） |

## 全体構成

```
用語集 *.md (323件)
   │  ① 抽出・整形・伏字化
   ▼
quartz/tools/build-flashcards.mjs
   │  ② JSONを埋め込んだ単一HTMLを出力
   ▼
quartz/static/flashcards/index.html   ← git管理下
   │  ③ Quartzビルド（Static emitter がコピー）
   ▼
public/static/flashcards/index.html
   │
   ▼
https://tyoshida0413-ai.github.io/ap-exam-textbook/static/flashcards/
```

入口となる一覧ページは通常の Markdown ページとして別に用意し、上記URLへリンクする。

## 各コンポーネント

### 1. 生成スクリプト `quartz/tools/build-flashcards.mjs`

**役割**：用語集Markdownからカードデータを作り、完成品のHTMLを1ファイル出力する。

**入力**：`content/用語集/{09_データベース,10_ネットワーク,11_セキュリティ}/*.md`

**抽出処理**：

1. frontmatter から `title`・`aliases`・`分野` を取得
2. 本文のH1見出しを探し、その直後（空行は読み飛ばす）から連続する `>` 行を集める
3. 複数行は半角スペースで連結して1文にする
4. `[[X]]` → `X`、`**X**` → `X`、`` `X` `` → `X` に変換し、連続空白を1つに畳む

**伏字化処理**：

定義文に含まれる `title` および全 `aliases` を `〇〇〇` に置換する。
文字数の長い語から順に置換し、部分一致による断片化を抑える。置換後、連続した `〇〇〇` は1つに畳む。

**頭字語の展開形も伏せる。** `title` / `aliases` の完全一致だけでは、
「Web Application Firewall」（答え `WAF`）のような**英語正式名称による露出**を捕まえられない。
問題文中の英単語列の頭文字を繋いで答えと一致するものを探し、一致した範囲を伏字にする。
`and` `of` `the` などの連結語は頭文字に数えない（`DMARC` の展開形を取りこぼさないため）。
この対策で追加12件の露出が解消した。

**文頭の伏字を整える。** 展開形が文頭にあった場合、
`〇〇〇（証明書失効リスト）。…` → `証明書失効リスト。…`、`〇〇〇。…` → `…` に整形する。

自動処理では不自然になる以下2件は、スクリプト内の手動上書きリストで問題文を差し替える。

| 用語 | 自動処理の結果 | 対応 |
|---|---|---|
| `DoS攻撃` | 「複数拠点から行うものを**D〇〇〇**という」と断片が残る | 問題文を手書きで差し替え |
| `CSMA/CD` | 展開形の伏字化だけでは日本語名と噛み合わず不自然になる | 問題文を手書きで差し替え |

**出力**：`quartz/static/flashcards/index.html`
カード配列（`{q, a, aliases, cat}` の323要素）を `<script>` タグ内のJSONとして埋め込む。

**カテゴリ識別子**：

| フォルダ | 識別子 | 表示名 |
|---|---|---|
| `09_データベース` | `database` | データベース |
| `10_ネットワーク` | `network` | ネットワーク |
| `11_セキュリティ` | `security` | セキュリティ |

### 2. フラッシュカードページ（単一の自己完結HTML）

外部リクエストを一切行わない。CSS・JS・データはすべて同一ファイルに内包する。

**出題**

- 表：伏字化した定義文
- 裏：用語名。alias があれば併記する
- カードをクリック（タップ）でめくる

**カテゴリ絞り込み**

URLハッシュ `#database` / `#network` / `#security` で対象を切り替える。
指定が無い、`#all`、または未知の値の場合は全件を対象とする（記法の根拠は入口ページの節を参照）。

ページ上部にもカテゴリ切替を置き、学習中でも移動できるようにする。
ハッシュ方式のため再読み込みは発生しない。

**ランダム表示**

ページを開いた時点で Fisher-Yates シャッフル済みの順序で出題する。
「シャッフル」ボタンで再抽選できる。

**仕分けと再出題**

各カードに「覚えた」「まだ」を記録する。1周し終えたら結果を表示し、「まだ」に入れたカードだけを再びシャッフルして出題できる。
記録はページを閉じると消える（永続化しない）。

**その他のUI**

- 進捗表示（例：`12 / 141`）
- 前へ／次へ
- テーマ切替ボタン

**テーマ**

Quartz本体のテーマには追従しない。ページが独自にライト／ダークを持つ。

- 初期値は `prefers-color-scheme` に従う
- 切替ボタンで手動変更でき、選択内容は独自の localStorage キーに保存する
- 配色は `quartz.config.yaml` の `colors.lightMode` / `colors.darkMode` の値を写して、サイトと同系統の見た目にする

### 3. 入口ページ `暗記カード.md`

**配置場所**：iCloud側の応用情報フォルダ直下
`.../002.Privates/勉強/応用情報技術者試験/暗記カード.md`

`content/` は `sync-content.sh` の `rsync --delete` によって毎回上書きされるコピーであるため、直接編集してはならない。

**内容**：4つのリンクを並べる。

- データベース（77語）→ `?cat=database`
- ネットワーク（105語）→ `?cat=network`
- セキュリティ（141語）→ `?cat=security`
- 全カテゴリ（323語）→ クエリなし

Explorer プラグインが有効なため、content直下に置かれたこのページは左サイドバーのファイルツリーに自動的に並ぶ。

**リンクの記法（実測により決定）**

`quartz.config.yaml` の `baseUrl` は `tyoshida0413-ai.github.io/ap-exam-textbook` であり、サイトはサブパス配下に配信される。
そのためルート絶対パス `/static/flashcards/` は `/ap-exam-textbook` が抜けた誤ったURLになる。

リンク記法6種を実際にビルドして出力 `href` を実測した結果は次のとおり。

| Markdown の記法 | ビルド後の `href` | 可否 |
|---|---|---|
| `./static/flashcards/?cat=database` | `./static/flashcards/cat=database` | ✗ `?` が消える |
| **`./static/flashcards/#database`** | **`./static/flashcards/#database`** | **✓ 採用** |
| `static/flashcards/?cat=database` | `./static/flashcards/cat=database` | ✗ |
| `<a href="./static/flashcards/?cat=database">` | `./static/flashcards/cat=database` | ✗ 生HTMLでも変換される |
| `https://…/static/flashcards/?cat=database` | そのまま保持 | △ ドメインが固定される |
| `./static/flashcards/index.html?cat=database` | `./static/flashcards/index.htmlcat=database` | ✗ |

Quartz のリンク変換はクエリ文字列の `?` を落とすが、**ハッシュは保持する**。
したがってカテゴリの指定は**クエリではなくハッシュ**（`#database`）で行う。
相対パスのままローカルプレビューでも動作し、ドメインをハードコードせずに済む。

ハッシュ方式の副次的な利点として、カテゴリ切替がページ再読み込みなしで行える
（`hashchange` を購読して再抽選する）。
なお、直接 `?cat=…` と入力された場合にも対応できるよう、クエリも読めるようにしておく。

### 4. `sync-content.sh` の変更

rsync の完了後、`npx quartz sync` の前に生成スクリプトの実行を挿入する。

```bash
rsync -a --delete ... "$SRC/" "$SCRIPT_DIR/content/"

node quartz/tools/build-flashcards.mjs   # ← 追加

cd "$SCRIPT_DIR"
npx quartz sync
```

更新手順は従来どおり `./sync-content.sh` の1コマンドのままとする。

## 設計上の判断と根拠

**静的アセットとして置く理由**
Quartz の Markdown 処理系を通さないため、独自のHTML・CSS・JSをそのまま配信できる。
また `custom.scss` の読み込み順の制約（レイヤー内外の優先度問題）を回避できる。

**`quartz/static/` に生成する理由**
`public/` は `.gitignore` の対象であり、GitHub Actions 側でビルドされる。
一方 `quartz/static/` は git 管理下にあるため、生成物がリポジトリ経由で CI に届く。

**永続化しない理由**
学習の進捗をサーバーに保存する要件は無い。既存の付箋機能とは独立させ、実装を単純に保つ。

## 想定される失敗と対処

| 事象 | 対処 |
|---|---|
| 用語集に blockquote の無いファイルが将来追加される | 生成時に警告を出し、そのファイルはスキップして処理を継続する |
| 伏字化後の問題文が空、または極端に短くなる | 生成時に警告を出し、目視確認できるようにする |
| 新しい用語で答えの露出が発生する | 生成時に「定義文に答えが残っている件数」を出力し、検知できるようにする |

## 検証結果（2026-08-04 実測）

生成物から独立に検証した。スクリプトの自己申告ではなく、出力HTMLから埋め込みJSONを取り出して測っている。

| 項目 | 結果 |
|---|---|
| カード件数 | 320（database 76／network 104／security 140） |
| 問題文に答えが完全一致で残存 | 0件 |
| 問題文に頭字語の展開形が残存 | 0件 |
| 問題文が空・10字未満 | 0件 |
| Markdown記法の残骸（`[[` `**` `` ` ``） | 0件 |
| 答えの重複 | 0件 |
| 文頭に伏字が残存 | 0件 |
| 外部リソース参照 | 0件 |
| 通信API（fetch / XHR / WebSocket）の使用 | 0件 |

ブラウザ動作はヘッドレスChrome + CDPで実測した（**48項目すべて合格**）。
検証したのは、初期表示、ハッシュによるカテゴリ直リンク（3種）、リロードなしのカテゴリ切替、
めくる操作、覚えた／まだの仕分けと進捗、前へ戻る、キーボード操作、シャッフル、
1周後の結果画面と「まだ」だけの再出題、テーマ切替と保存の永続化、
デスクトップ（1200px）とスマートフォン（390px）での横スクロール発生の有無、JSエラーの有無。

なお「開き直すと順序が変わる」の検証では、同一URLへの `Page.navigate` が実際にはリロードを起こさず
一度不合格と出た。`Page.reload` で測り直したところ4回とも異なる順序になり、テスト側の問題と判明した。

## 対象外とすること

- 学習履歴の永続化・端末間同期
- 間隔反復（SRS）アルゴリズム
- カードの手動追加・編集UI
- 用語集以外のコンテンツ（教科書本文など）のカード化
